# BUG-051 – A database that fails to open leaves its file locked

| Field | Value |
|---|---|
| Module / Category | Database / Data Integrity |
| Severity / Priority | Medium / Medium |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
The first GitHub Actions run on Windows failed `test_bug_027_real_corrupt_file_triggers_the_message` with `PermissionError: [WinError 32] ... bad.db is being used by another process`. Linux lets you delete an open file, so every local run passed.

## Root cause
`initialize_database` closed its connection only when everything succeeded. When a statement failed, the connection stayed open until the process ended. On Windows the damaged file then cannot be moved or replaced, which blocks a restore from backup while the error window is showing.

## Fix
`app/database/db.py`: schema creation moved to `_create_schema(conn)` and called inside `try/finally`.

## Other Windows test failures fixed in the same run
Three `test_timestamps` tests used `time.tzset()`, which does not exist on Windows. They now skip themselves there (the time-zone conversion itself is not Windows-specific and is covered on Linux).

## Test
`tests/test_startup_errors.py::test_bug_051_*` (fails without the fix on any platform). Full suite: 263 tests OK (18 UI tests skipped without a display).
