# BUG-046 – Administrator password reset leaves the account locked and the password never expires

| Field | Value |
|---|---|
| Module / Category | Other (accounts) / Security |
| Severity / Priority | Medium / Medium |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Reviewing the account functions after BUG-025 (lockout) and BUG-028 (forced change). `change_password`, used by the administrator to reset another user's password, still wrote `must_change_password = 0` and did not touch `failed_attempts` / `locked_until`.

## Impact
A user locked out after five wrong tries stayed locked for the rest of the five minutes even after the reset, and the password the administrator chose (and therefore knows) never had to be replaced.

## Fix
`change_password` clears the lockout and sets `must_change_password = 1`, except when the administrator resets their own account.
