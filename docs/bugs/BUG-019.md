# BUG-019 – Action services still accept True / 1.9 as record IDs

| Field | Value |
|---|---|
| Module / Category | Complaint (all services) / Validation |
| Severity / Priority | Low / Medium |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Follow-up to BUG-017: `assign_complaint(True, "Ravi")` succeeded and changed complaint 1. Only the create paths had been fixed.

## Root cause
The assign, resolve, return, release, delete, approve, password and bug-status functions passed the raw ID to SQLite, which treats `True` as 1.

## Fix
`validate_record_id` is called at the start of: `assign_complaint`, `resolve_complaint`, `mark_returned`, `release_allocation`, `delete_room`, `update_student`, `delete_student`, `delete_event`, `delete_user`, `approve_user`, `change_password`, `start_progress`, `close_bug`.

## Test
`tests/test_bug_fixes.py::test_bug_019_status_and_delete_actions_reject_bool_and_fraction_ids` (fails without the fix). Full suite: 217 tests OK.
