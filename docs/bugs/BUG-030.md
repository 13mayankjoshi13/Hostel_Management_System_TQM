# BUG-030 – Same registration number can be added twice in different letter case

| Field | Value |
|---|---|
| Module / Category | Student / Data Integrity |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Probed `add_student("…", "bt24a0007")` after adding `BT24A0007`: both were stored as separate students. The registration number is what ties a student to a sign-up and an account, and sign-up looked it up with an exact match.

## Root cause
Registration numbers were stored and compared exactly as typed; the database `UNIQUE` rule is case-sensitive.

## Fix
- `validate_registration_number` returns the number in upper case.
- Duplicate checks (`add_student`, `update_student`) and the sign-up lookup compare `UPPER(...)`, so older rows saved in lower case still match.
- `db.py`: unique index on `UPPER(registration_number)`; skipped if existing data already has such duplicates (index creation errors no longer stop start-up).

## Test
`tests/test_bug_fixes.py::test_bug_030_registration_numbers_are_case_insensitive` (fails without the fix). Full suite: 231 tests OK.

## Not covered
Existing duplicates already in a database are not merged; they only prevent the new index from being created.
