# BUG-032 – Users cannot change their own password

| Field | Value |
|---|---|
| Module / Category | Other (authentication) / Security |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Walked through each role. Only the Administrator's Users screen could set a password (for anyone). A student, warden or staff member who thought their password was known had no way to change it, and every password an administrator handed out stayed in use. This was also listed as a known gap since the sign-up work.

## Root cause
Only an admin-side `change_password` existed.

## Fix
- `auth_service.change_own_password(current, new)`: needs a logged-in session and the correct current password; the new one must pass the normal rules, differ from the current one, and not be a known default (`admin123`, `Welcome123`). Clears any "must change" flag and is audit-logged.
- `main_window.py`: a **Change password** link above Log out, for every role (current / new / repeat prompts).

## Test
`tests/test_bug_fixes.py::test_bug_032_users_can_change_their_own_password` (fails without the fix). Also driven in a real window: mismatch, wrong current password, success, cancel. Full suite: 235 tests OK.

## Not covered
The sidebar prompt flow is not in the automated tests.
