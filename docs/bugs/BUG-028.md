# BUG-028 – Default admin / admin123 is never forced to change its password

| Field | Value |
|---|---|
| Module / Category | Other (authentication) / Security |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Reviewed first-run set-up: `ensure_default_admin` creates `admin` / `admin123` (the password is even written into the audit log) and nothing ever asks for it to be changed. A deployed system keeps a publicly known Administrator login.

## Root cause
No "must change password" state and no first-login prompt.

## Fix
- `users.must_change_password` (auto-migrated).
- New default admin is created flagged; on start-up an existing `admin` account that still uses `admin123` is flagged too.
- After login the main window asks for a new password before showing anything (rules: normal password rules, and not `admin123`); cancelling logs the user out.
- `change_password` (Users screen) rejects `admin123` and clears the flag. New `complete_forced_password_change`.
- `authenticate` returns `must_change_password`.

## Test
`tests/test_bug_fixes.py::test_bug_028_*` (3 tests: forced change flow, flagging an existing database, admin reset cannot reuse the default). Fails without the fix. Also driven in a real Tk window (retry on bad input, success, cancel). Full suite: 229 tests OK.

## Not covered
Other accounts are not forced to change a password an administrator set for them. Students still cannot change their own password.
