# BUG-047 – Backups live on the same disk as the database

| Field | Value |
|---|---|
| Module / Category | Database / Data Integrity |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Known gap since BUG-031: daily backups were written to `app/database/backups/`, next to `hostel.db`. One disk failure, or deleting the project folder, loses the database and all backups together.

## Fix
`app/database/backup.py`: if the environment variable `HOSTEL_EXTRA_BACKUP_DIR` names a folder (another drive, USB stick, synced folder), each new backup is also copied there and pruned to the same 7 copies. If the copy fails the error is logged (`BackupCopyError`) and start-up continues.

Windows example: `setx HOSTEL_EXTRA_BACKUP_DIR "D:\HostelBackups"` (then reopen the terminal). To restore: `python -m app.database.backup restore D:\HostelBackups\hostel_YYYYMMDD_HHMMSS.db`.

## Test
`tests/test_backup.py::test_bug_047_*` (fails without the fix). Full suite: 258 tests OK (18 UI tests skipped without a display).

## Not covered
The variable is optional and unset by default, so the machine owner must set it.
