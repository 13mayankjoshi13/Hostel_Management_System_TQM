# BUG-027 – App exits silently when the database cannot be opened

| Field | Value |
|---|---|
| Module / Category | Database / Functional |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Probing failure paths. With a damaged (non-SQLite) database file, `run()` logged the error and then only `print()`ed it to stderr before returning. A user starting the app by double-click has no console, so the window simply never appears and nothing explains why. The final catch-all for a crash of the main window had the same problem. (Checked and fine: unwritable log files never break a service, because the loggers never raise.)

## Root cause
Start-up failures were reported on stderr only.

## Fix
`app/main.py`: `show_fatal` shows a message window (and still prints to stderr). The database message includes the error, the error id from the log, and what to check (file locked by another program or damaged). The "unexpected error" path uses it too.

## Test
`tests/test_startup_errors.py` (`test_bug_027_*`): a failing `initialize_database`, and a real corrupt file. Fails without the fix. Full suite: 226 tests OK.

## Not covered
The message window itself (real Tk dialog) is mocked in tests.
