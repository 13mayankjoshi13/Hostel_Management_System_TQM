# BUG-014 — Complaint, leave and bug tables lose the selected row after every action

| Field | Value |
|---|---|
| Module / Category | UI / UI/UX |
| Severity / Priority | Low / Medium |
| Status | Fixed (close it in the Bug screen after re-testing) |

## How it was found
Noted while driving the screens for BUG-013, then confirmed: select a complaint, click Assign Selected, then click Resolve Selected.

```
assign:  Complaint assigned.
resolve: Select a complaint first.     <- the row was no longer selected
```

The same happened on the Leave screen after Mark Returned and on the Bug Tracker after Start Progress (then Mark Fixed). Same family as BUG-012.

## Root cause
The refresh methods deleted and re-inserted every row after each action, which clears the selection, and nothing restored it.

## Fix
- `app/theme.py`: new `keep_selection(tree, rebuild)` remembers the selected rows by their first column (the ID), runs the rebuild, and selects the same rows again.
- `complaint_screen.py`, `leave_screen.py`, `bug_screen.py` refresh through it.
- `bug_screen.py` also re-draws the detail text after a refresh and shows the "Select a bug" hint when the selected row is filtered out.

## Test
`tests/test_selection_ui.py` — `test_bug_014_*` (assign then resolve works without re-clicking, leave and bug selection kept, detail updates, filtered-out row clears cleanly). They need a display and skip without one. With `keep_selection` disabled, 3 of 4 fail. Full suite: 210 tests.
