# BUG-035 – Defect log CSV has no reporter or fixer, and write failures are silent

| Field | Value |
|---|---|
| Module / Category | Other (logging) / Data Integrity |
| Severity / Priority | High / Medium |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
`TQM/data/defect_log.csv` is the evidence file for the Bug Tracker feature, yet it had no reporter or fixer, although the app has shown both since Batch 29. Adding the columns exposed a second problem: `log_defect` swallows every error ("never raises"), and an existing log file with the old header makes the new, wider rows fail, so every new defect row would have been dropped without a trace.

## Root cause
CSV columns fixed before reporter/fixer existed; no upgrade path for older files; failed writes ignored.

## Fix
`app/utils/logging_service.py`:
- `reported_by` and `fixed_by` columns in the defect log, filled from `bug_service` at create, start, fix and close.
- `_upgrade_header`: an older log file is rewritten in place with the current header (old rows keep blank values) before a row is appended. Applies to all three logs.
- A failed defect write is now recorded in the error log instead of vanishing.

## Test
`tests/test_bug_fixes.py::test_bug_035_defect_log_records_people_and_upgrades_old_files` (old-format file, full bug lifecycle; fails without the upgrade). Full suite: 241 tests OK.

## Not covered
Rows written before this fix have blank reporter/fixer; the database holds the real values.
