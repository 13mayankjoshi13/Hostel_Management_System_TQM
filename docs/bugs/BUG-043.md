# BUG-043 – Restore accepts any SQLite file; a failed backup leaves a partial file

| Field | Value |
|---|---|
| Module / Category | Database / Data Integrity |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Review of `app/database/backup.py` (BUG-031). Restore only ran `PRAGMA integrity_check`, which any healthy SQLite file passes, so choosing the wrong file replaced the live database. A backup interrupted by a full disk left a partial `.db` that the "one backup per day" rule then treated as today's backup.

## Fix
`restore_backup` requires the six hostel tables (`students`, `rooms`, `allocations`, `complaints`, `leaves`, `users`); `create_backup` removes the partial file and re-raises when the copy fails.

## Test
`tests/test_backup.py::test_bug_043_*` (fails without the fix). Full suite: 254 tests OK (18 UI tests skipped without a display, as before).
