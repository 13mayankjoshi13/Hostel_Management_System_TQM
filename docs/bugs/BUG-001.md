# BUG-001 — Room type and capacity are not checked against each other

| Field | Value |
|---|---|
| Module / Category | Room / Validation |
| Severity / Priority | Medium / Medium |
| Status | Fixed (close it in the Bug screen after re-testing) |

## How it was found
Exploratory input testing: a script called `room_service.add_room` with unusual combinations and printed what was stored.

```python
room_service.add_room("Z4", "Single", 5)   # accepted — expected a rejection
```

Other checks in the same run behaved correctly (empty name, digits in name, capacity 0 or 1000, bad room type, leave end before start).

## Root cause
`add_room` validated the room type and the capacity separately (`validate_room_type`, `validate_capacity`). Nothing linked them, so a Single room could hold 5 students.

## Fix
- `app/utils/validation.py`: new `validate_type_capacity` with Single = 1, Double = 2, Triple = 3, Dormitory = 4 to 10.
- `app/services/room_service.py`: `add_room` calls it after the two existing checks, before any database write.

The capacity rule is my assumption of what each type means; change `_CAPACITY_BY_TYPE` if your hostel differs.

## Test
`tests/test_bug_fixes.py` — `test_bug_001_*` (mismatches rejected, matches accepted). The full suite passes (154 tests).

## Tracker entry
`python -m app.database.log_bugs` adds this bug to the database and `TQM/data/defect_log.csv` with the root cause, corrective action and test case, ending at Fixed.
