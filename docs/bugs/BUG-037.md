# BUG-037 – Login reveals which usernames exist

| Field | Value |
|---|---|
| Module / Category | Other (authentication) / Security |
| Severity / Priority | Medium / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Timed failed logins. A wrong password for a real username took about 60 ms (the password hash is computed); an unknown username answered in about 0.3 ms. After BUG-025, a locked real account also said "Too many failed attempts" while an unknown name never did. Both let someone list valid usernames (which follow student names) before guessing passwords.

## Root cause
The hash was computed only for existing accounts, and the lockout message was specific to them.

## Fix
`app/services/auth_service.py`: unknown and locked accounts check a dummy hash so every failure takes about the same time, and every failed login (including a locked account with the right password) returns one message: "Invalid username or password. An account is locked for 5 minutes after 5 failed attempts." Lockout itself is unchanged.

## Test
`tests/test_bug_fixes.py::test_bug_037_login_does_not_reveal_which_usernames_exist` (same message for known, unknown and locked; unknown-user time no longer far below known; fails without the dummy hash). The BUG-025 test now checks the new wording. Full suite: 243 tests OK.

## Not covered
Sign-up still says when a username is taken (needed so people can pick another). The pending-approval message appears only after a correct password.
