# BUG-003 — Room numbers differing only in letter case are stored as separate rooms

| Field | Value |
|---|---|
| Module / Category | Room / Data Integrity |
| Severity / Priority | Medium / Medium |
| Status | Fixed (close it in the Bug screen after re-testing) |

## How it was found
Same input-testing run as BUG-001. Adding the same room number in two cases:

```python
room_service.add_room("Q1", "Single", 1)   # created
room_service.add_room("q1", "Single", 1)   # also created — expected "already exists"
```

The Room list then showed `Q1` and `q1`, so one physical room could be allocated twice.

## Root cause
`add_room` checked for duplicates with `room_number = ?`, which is case-sensitive in SQLite, and stored the number exactly as typed.

## Fix
- `validate_room_number` now returns the number in upper case, so new rooms are stored as `B12`, never `b12`.
- `add_room` checks duplicates with `UPPER(room_number) = ?`, so a mixed-case room already in an old database still blocks a duplicate.

Existing mixed-case rooms in your database are not renamed.

## Test
`tests/test_bug_fixes.py` — `test_bug_003_*` (case duplicate rejected, stored in upper case, existing mixed-case room blocks a duplicate). Full suite: 159 tests pass.
