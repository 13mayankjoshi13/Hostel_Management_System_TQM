# BUG-025 – Login has no limit on wrong passwords

| Field | Value |
|---|---|
| Module / Category | Other (authentication) / Security |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Reviewed `authenticate`: it verifies the password on every call and keeps no record of failures, so any number of guesses can be tried against any account, including the default `admin` account.

## Root cause
No failed-attempt tracking.

## Fix
- `app/database/db.py`: `users.failed_attempts` and `users.locked_until` (auto-migrated).
- `app/services/auth_service.py`: after 5 wrong passwords in a row the account is locked for 5 minutes (stored in the database, so restarting the app does not reset it). While locked, even the correct password is refused. A successful login clears the count. Lockouts are written to the audit log.

## Test
`tests/test_bug_fixes.py::test_bug_025_repeated_wrong_passwords_lock_the_account` covers lock, expiry, reset on success. Fails without the fix. Full suite: 223 tests OK.

## Trade-off
Someone who knows a username can lock that account for 5 minutes by guessing wrongly. Unknown usernames are not tracked.
