# BUG-002 — Contact number accepts numbers that cannot be Indian mobiles

| Field | Value |
|---|---|
| Module / Category | Student / Validation |
| Severity / Priority | Medium / Medium |
| Status | Fixed (close it in the Bug screen after re-testing) |

## How it was found
The same input-testing run as BUG-001. Calling `student_service.add_student` with different contacts:

```python
add_student("Ab Cf", "2410302006", "0123456789")   # accepted
add_student("Ab Cg", "2410302007", "5123456789")   # accepted
add_student("Ab Ce", "2410302005", "+919876543210")  # rejected (correct)
```

A follow-up check showed `str.isdigit()` also passes non-ASCII digits (for example Arabic-Indic `٩٨٧٦٥٤٣٢١٠`).

## Root cause
`validate_contact_number` only checked "digits only" and "length 10". Indian mobile numbers start with 6, 7, 8 or 9, and `isdigit()` is not limited to 0-9.

## Fix
`app/utils/validation.py`, `validate_contact_number`:
- require ASCII digits (`isascii() and isdigit()`);
- require the first digit to be 6, 7, 8 or 9.

Existing stored contacts are not changed. The loader's made-up numbers already start with 6-9.

## Test
`tests/test_bug_fixes.py` — `test_bug_002_*` (invalid numbers rejected, 6/7/8/9 starts accepted). Full suite: 156 tests pass.
