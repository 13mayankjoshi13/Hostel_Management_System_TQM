# BUG-045 – A student session can act on other students' leaves and complaints

| Field | Value |
|---|---|
| Module / Category | Allocation (leave and complaints) / Security |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
A scan of every service function for a permission check, then a probe with a Student session. `record_leave`, `mark_returned` and `create_complaint` accepted any student id. The portal only checked ownership for "return from leave", so a modified or future screen could create leaves and complaints in another student's name, or end another student's leave.

## Fix
`session.require_own_or_staff(student_id, action)`: staff roles pass, a Student session passes only for its own student id. Called in `record_leave`, `mark_returned` (against the leave's owner) and `create_complaint`.

## Test
`tests/test_bug_fixes.py::test_bug_045_*` (fails if the check is removed from either the leave or the complaint service). Full suite: 256 tests OK (18 UI tests skipped without a display).
