# BUG-029 – All loaded student accounts share one known password

| Field | Value |
|---|---|
| Module / Category | Other (authentication, data loader) / Security |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Reviewed `seed_demo` (the real-class loader). Every student login it creates uses `Welcome123`, and usernames follow the student's name (`mayank_joshi`). Anyone in the class could sign in as another student and see or change their room, complaints, leave and details.

## Root cause
Shared password, no requirement to change it. (Same class of problem as BUG-028.)

## Fix
- `auth_service.create_user(..., must_change_password=False)`; the loader passes `True`, so first login shows the forced password prompt from BUG-028.
- `Welcome123` (`SEED_PASSWORD`) joins `admin123` in `KNOWN_DEFAULT_PASSWORDS`, which can no longer be chosen as a new password.
- `flag_accounts_using_seed_password()` flags existing accounts that still use it; the loader runs it every time, so re-running `python -m app.database.seed_demo --real` on an existing database fixes accounts that were already created.

## Test
`tests/test_bug_fixes.py::test_bug_029_shared_demo_password_must_be_replaced` plus a new assertion in `tests/test_seed_demo.py`. Fails without the fix. Full suite: 230 tests OK.

## Not covered
Accounts are flagged only by re-running the loader; there is no automatic check at every start-up (it would add about 3 seconds for 56 accounts).
