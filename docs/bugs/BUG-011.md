# BUG-011 — Registration number, room number and username accept look-alike non-ASCII characters

| Field | Value |
|---|---|
| Module / Category | Other (validation of identifiers) / Security |
| Severity / Priority | Medium / Medium |
| Status | Fixed (close it in the Bug screen after re-testing) |

## How it was found
Follow-up to the BUG-010 name tests. The identifier validators were fed look-alike input:

```
validate_registration_number("٢٤١٠٣٠٢٠٣٧")   # Arabic-Indic digits  -> accepted
validate_registration_number("0000000000")    # all zeros            -> accepted
validate_username("аdmin")                    # Cyrillic 'а'         -> accepted
```

A username like `аdmin` looks identical to `admin` on screen, so it can impersonate another account; a registration number in other digits would never match the one on the hostel list and could not be found by search.

## Root cause
The validators used `str.isalnum()`, which is true for letters and digits of every script. BUG-002 had the same cause in the contact number.

## Fix
`app/utils/validation.py`:
- `validate_registration_number`, `validate_room_number` and `validate_username` require ASCII letters and digits (usernames also allow `_`);
- a registration number cannot be all zeros.

## Test
`tests/test_bug_fixes.py` — `test_bug_011_*` (look-alike input rejected, normal values still accepted). Full suite: 200 tests pass.

## Tracker entry
`python -m app.database.log_bugs` adds BUG-011 (reporter and fixer: Mayank) and skips the ones already logged.

## Not changed
Student names may still contain non-English letters (for example `Ünal`), because real names need them. Records already saved are not re-checked.
