# BUG-023 – Student session can call staff and admin services directly

| Field | Value |
|---|---|
| Module / Category | Other (all services) / Security |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Logged a Student session and called services directly. `add_student`, `delete_student`, `add_room`, `release_allocation`, `change_password` and `create_user("hax", ..., "Administrator")` all succeeded. Only the sidebar hid the screens.

## Root cause
Role rules lived only in the navigation (`_allowed_screens`); most services never checked the caller's role.

## Fix
`session.require_roles` (plus `STAFF_ROLES`) raises a `ValidationError` for a disallowed role.
- Staff roles (Administrator, Warden, Staff): add/list/delete students, add/delete rooms, allocate/release, assign/resolve complaints, log and change bugs.
- Administrator only: create, delete and list accounts, change passwords (approval already was).
- Left open to students: filing complaints and leaves, and returning from leave, which go through `student_portal_service`.

With nobody logged in, the configured fallback role (Administrator) still applies, so scripts like `seed_demo` and `log_bugs` keep working.

## Test
`tests/test_bug_fixes.py::test_bug_023_services_enforce_roles` (fails without the fix). Test setup now clears the session so tests don't leak roles. Full suite: 221 tests OK.
