# BUG-042 – Error log breaks after an Excel re-save; error IDs can repeat

| Field | Value |
|---|---|
| Module / Category | Other (logging) / Data Integrity |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Follow-up to BUG-041. A log re-saved by Excel on Windows is often in cp1252, not UTF-8. The header check raised `UnicodeDecodeError` (not an `OSError`), which the logger swallowed, so every later error returned `ERR-UNLOGGED` and nothing was recorded. Separately, IDs were row count + 1: a deleted row, or a read problem, made an old ID repeat, and rows waiting in `.pending` were not counted.

## Fix
`app/utils/logging_service.py`: `_next_id` uses the highest existing number + 1 (CSV read leniently, plus `.pending` rows); `_repair_encoding` converts a non-UTF-8 log back to UTF-8 before appending; `_upgrade_header` reads leniently.
