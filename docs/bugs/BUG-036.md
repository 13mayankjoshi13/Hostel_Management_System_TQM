# BUG-036 – A student session can read every student's complaints, allocations and the allotment export

| Field | Value |
|---|---|
| Module / Category | Allocation, Complaint, Leave, Bug / Security |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Follow-up to BUG-023, which protected writes. Calling the read functions with a Student session: `get_all_complaints` returned another student's complaint, `get_active_allocations` returned every student's name and room, and `export_allocation_list` wrote the full allotment list to a file. Only the screens were hidden.

## Root cause
The read functions had no role check; privacy rules lived only in the navigation.

## Fix
`session.require_roles(session.STAFF_ROLES, ...)` at the start of `get_all_complaints`, `get_all_leaves`, `get_active_allocations`, `export_allocation_list` and `get_all_bugs`. Students keep their own data through `student_portal_service`, which filters by the logged-in student.

## Test
`tests/test_bug_fixes.py::test_bug_036_students_cannot_read_other_peoples_records` (fails without the fix; also checks the export file is not created and a Warden still works). Full suite: 242 tests OK.

## Not covered
`get_all_rooms` (room numbers, types, capacity; no student data) stays readable.
