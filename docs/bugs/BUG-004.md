# BUG-004 — Room capacity silently converts 1.5 and True to 1

| Field | Value |
|---|---|
| Module / Category | Room / Validation |
| Severity / Priority | Low / Low |
| Status | Fixed (close it in the Bug screen after re-testing) |

## How it was found
Same input-testing run as BUG-001. Calling the service directly with non-integer values:

```python
room_service.add_room("Q4", "Single", 1.5)   # created with capacity 1
room_service.add_room("Q5", "Single", True)  # created with capacity 1
```

The Room screen sends text, and `"1.5"` was already rejected there, so this affects code that calls the service directly (imports, scripts, future screens). It is why the severity is Low.

## Root cause
`validate_capacity` called `int(capacity)` straight away. `int(1.5)` truncates to 1, and `True` is an `int` subclass equal to 1.

## Fix
`app/utils/validation.py`, `validate_capacity`: reject `bool` and non-integral floats before the `int()` conversion. `1`, `"1"` and `1.0` are still accepted.

## Test
`tests/test_bug_fixes.py` — `test_bug_004_*`. Full suite: all tests pass (see below).
