# BUG-006 — Leave dates accept impossible ranges (year 1900, multi-year leaves)

| Field | Value |
|---|---|
| Module / Category | Other (leave tracking) / Validation |
| Severity / Priority | Medium / Medium |
| Status | Fixed (close it in the Bug screen after re-testing) |

## How it was found
Same round of exploratory testing as BUG-005:

```python
leave_service.record_leave(s1, "1900-01-01", "1900-01-02", "long ago")   # recorded
leave_service.record_leave(s1, "2026-10-30", "2031-10-30", "wow")        # only stopped because another leave was open
```

## Root cause
`validate_leave_dates` checked the date format and that the end is not before the start, nothing else.

## Fix
`app/utils/validation.py`, `validate_leave_dates`:
- a leave cannot be longer than 180 days (`MAX_LEAVE_DAYS`);
- start and end must be within one year of today (past leaves can still be back-recorded).

Both limits are my choice; change `MAX_LEAVE_DAYS` or the one-year window if your hostel rules differ.

## Side effect handled
The older tests and the demo-data loader used fixed October 2026 dates, which would have started failing once those dates fell outside the one-year window. I changed them to dates relative to today (`test_leave.py`, `test_student_portal.py`, `seed_demo.py`), so they keep working.
