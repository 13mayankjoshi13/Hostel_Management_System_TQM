# BUG-050 – A packaged .exe would lose all data on every exit

| Field | Value |
|---|---|
| Module / Category | Database / Data Integrity |
| Severity / Priority | Critical / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Reviewing the release build (PyInstaller `--onefile`) before the first GitHub release. `app/config.py` derives every path from the source folder. In a one-file build that folder is a temporary directory created at start-up and deleted at exit, so the database, the daily backups and the CSV logs would be created there and lost each time the program closed. The tests and a normal `python run.py` never show this.

## Fix
`app/config.py`: when `sys.frozen` is set, data is stored under `%LOCALAPPDATA%\HostelManagementSystem` (database and backups there, logs in its `logs` folder). Source runs keep `app/database/` and `TQM/data/`. Uninstalling is deleting the `exe`; the data stays until that folder is removed.

## Test
`tests/test_packaged_paths.py` (fails without the fix). Full suite: 262 tests OK (18 UI tests skipped without a display).

## Not covered
The .exe itself can only be built and run on Windows; this was verified by simulating the frozen environment, not by running a real build. First release: run the app once from the downloaded .exe, add a student, close it, reopen, and confirm the student is still there.
