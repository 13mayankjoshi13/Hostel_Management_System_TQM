# BUG-026 – Errors inside button/timer callbacks are never logged or shown

| Field | Value |
|---|---|
| Module / Category | UI / Functional |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
Reviewed the Exception Handling feature (Q09 #1). `app/main.py` says any exception escaping the GUI is caught, logged and reported. Raising an error inside a Tk callback showed otherwise: Tkinter never lets callback exceptions out of `mainloop()`, so `run()`'s `try/except` cannot see them. By default Tk only prints a traceback to the console, so nothing reached `error_logs.csv` and the user saw no message.

## Root cause
No `report_callback_exception` handler was installed on the main window.

## Fix
- `app/utils/exception_handler.py`: `report_tk_callback_exception`, which logs the error (module `Application`, action `ui_callback`) and shows the usual "logged as ERR-xxxx" message.
- `app/screens/main_window.py`: installed on `MainWindow`.

## Test
`tests/test_callback_errors_ui.py::test_bug_026_exception_in_callback_is_logged_and_shown` (display required; fails without the fix). It installs the handler on a plain Tk root; the one-line install in `MainWindow` is not exercised by a test. Full suite: 224 tests OK.
