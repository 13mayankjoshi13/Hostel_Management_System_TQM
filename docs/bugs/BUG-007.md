# BUG-007 — Deleting a student or room that is in use shows a generic database error

| Field | Value |
|---|---|
| Module / Category | Other (student and room deletion) / Functional |
| Severity / Priority | Medium / Medium |
| Status | Fixed (close it in the Bug screen after re-testing) |

## How it was found
Second round of exploratory testing. With one student allocated to one room:

```python
room_service.delete_room(room_id)        # "Could not delete the room due to a database error."
student_service.delete_student(sid)      # "Could not delete the student due to a database error."
student_service.delete_student(999)      # reported success for a student that does not exist
```

Each failed delete also wrote a High-severity row to the error log, although nothing was wrong with the database.

## Root cause
`delete_room` and `delete_student` ran `DELETE` and relied on SQLite's foreign-key failure to stop the delete. The user got a generic message, the error log got a false High error, and a missing id was never checked.

## Fix
`app/services/room_service.py` and `app/services/student_service.py` now check before deleting:
- the record exists ("That room / student does not exist.");
- active allocation → "Release it first." message;
- any allocation, leave, complaint or login-account history → a message saying which records block the delete.

No data is deleted automatically and no database error is triggered. Unused records still delete normally.

## Test
`tests/test_bug_fixes.py` — `test_bug_007_*` (specific messages, history blocks delete, missing ids, unused records delete, no error-log rows). Full suite: 169 tests pass.

## Tracker entry
`python -m app.database.log_bugs` adds BUG-007 and skips the ones already logged.
