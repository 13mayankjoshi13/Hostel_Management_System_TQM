# BUG-038 – Sign-up can be used to guess a classmate's contact number

| Field | Value |
|---|---|
| Module / Category | Other (authentication, sign-up) / Security |
| Severity / Priority | High / High |
| Reported by / Fixed by | Mayank |
| Status | Fixed |

## How it was found
The sign-up form proves identity with the registration number plus the contact number on record. Registration numbers follow a predictable pattern and classmates know each other's numbers, but the form allowed unlimited tries, so someone could keep guessing a phone number until the pair matched. The administrator-approval step is the only other barrier, and the request would look genuine.

## Root cause
Failed sign-ups were not counted; only login (BUG-025) had a lockout.

## Fix
`signup_attempts` table (auto-created) and `auth_service.register_student`: failed attempts are counted per registration number, whether or not that number exists (so nothing is revealed). After 5 in a row the number is blocked for 15 minutes with a clear message; a successful sign-up clears the count.

## Test
`tests/test_bug_fixes.py::test_bug_038_*` (guessing a real student's contact; unknown numbers; lock expiry and reset). Fails without the lockout. Full suite: 245 tests OK.

## Not covered
A person who knows the real contact number can still sign up (approval is the control). Blocking a number also blocks the real student for 15 minutes, who can ask the hostel office.
